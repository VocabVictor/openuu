## Defects found

1. **Legacy signed-in session cannot connect.** Builds before the account gate
   stored the session only in the local `access_token`; the Rust gate
   (`src/account.rs`) reads the `openuu-account-token` option, so an upgraded
   install shows the user as signed in while every connection is refused with
   "Sign in to OpenUU before using remote connections". Fixed in 46d54296b
   (`UserModel._syncGateToken` copies the token to the gate key once the
   server confirms the session; 401/400 still resets both keys).
2. **`--import-config` does not carry `OpenUU2.toml`.** The installer flow
   (`sc create … --import-config <OpenUU.toml>`) copies only the ID/password
   file into the service profile; the custom rendezvous/relay/api/key options
   stay behind, so the service registers with `rs-ny.rustdesk.com` instead of
   the configured server. Worked around by copying `OpenUU2.toml` into
   `C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\OpenUU\config`.
   Assigned to session 8f (MSI fix).
3. **Signed-in controllers never reach the peer.** With an account token the
   client (`src/client/start_inner.rs`) secures the rendezvous TCP with a
   `KeyExchange` before sending `punch_hole_request`; the OpenUU hbbs has no
   `KeyExchange` handler, so the client waits 18 s and fails with
   "Failed to secure tcp: deadline has elapsed" without ever contacting the
   peer (confirmed with hbbs debug logs: two 18 s TCP sessions, no punch or
   relay records). Decision: implement `KeyExchange` in hbbs (session e9);
   client unchanged.

Observed but not verified: the empty-state "立即登录" button; peers in portable
mode inside an RDP session log `max ipc nack` from the portable service about
40 s after start (old and new builds alike) — retest after the service-mode
peers are back.
